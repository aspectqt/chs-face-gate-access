# System Diagnosis Report (2026-03-25)

## Root Cause

The dashboard change was being validated against generated HTML artifacts in `C:\Capstone Project`, not against the live Flask source files that the app serves after restart.

- `C:\Capstone Project\dashboard_logged_in.html` is written by `C:\Capstone Project\test_login_dashboard.py`.
- `C:\Capstone Project\dashboard_output.html` is written by `C:\Capstone Project\test_dashboard_content.py`.
- The actual running dashboard route is `/dashboard`, which renders `face-gate-access/backend/templates/dashboard.html` from `face-gate-access/backend/app.py`.

Because those standalone HTML files are only saved responses, any edits made there are not part of the application code and will never persist after restarting the server.

The PDF feature was not missing from source. The enhanced PDF export logic is still present in `face-gate-access/backend/app.py` and is wired to `/students/export_pdf`. The live students page still links to that route through `face-gate-access/backend/templates/students.html` and `face-gate-access/backend/static/students.js`.

## Fix Applied

Added regression coverage in `backend/tests/test_app_smoke.py` to lock the real runtime behavior:

- The dashboard test now asserts markers from the current minimalist dashboard template.
- The students test now asserts the export button is present and `/students/export_pdf` returns a valid PDF containing the enhanced report title.

This does not change the live UI or PDF logic; it prevents future confusion by verifying the actual served source files instead of generated artifacts.
